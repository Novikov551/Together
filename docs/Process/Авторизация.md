# Авторизация

## Общее описание

В Together один администраторский профиль (логин + пароль из конфига). Нет регистрации, нет ролей, нет нескольких пользователей. Все, кто знает логин/пароль — имеют одинаковые права.

## Процесс входа

```
Фронтенд                          Backend
    │                                 │
    │  POST /api/authorization/login  │
    │  { user_name, password }        │
    │ ──────────────────────────────→ │
    │                                 │  1. Извлечь AdminProfile из конфига
    │                                 │  2. Constant-time compare:
    │                                 │     FixedTimeEquals(request.user_name, config.user_name)
    │                                 │     FixedTimeEquals(request.password, config.password)
    │                                 │  3. Если не совпало → 401 "Неверный логин или пароль"
    │                                 │  4. Сгенерировать JWT:
    │                                 │     - Claim: Name = user_name
    │                                 │     - Expires: UTC + 1 час
    │                                 │     - Signing: HMAC-SHA256(Jwt:Secret)
    │                                 │  5. Вернуть { sessionToken }
    │  { sessionToken }               │
    │ ←────────────────────────────── │
```

## JWT-сессионный токен

- **Алгоритм**: HMAC-SHA256
- **Secret**: из `Jwt:Secret` (минимум 32 символа)
- **Claims**: `Name` = user_name
- **TTL**: 1 час
- **ClockSkew**: ноль (точное время)
- **ValidateIssuer**: false
- **ValidateAudience**: false

## Использование токена

Все защищённые endpoints требуют заголовок:
```
Authorization: Bearer <sessionToken>
```

## Безопасность

- `CryptographicOperations.FixedTimeEquals` — защита от timing attack
- Пароли хранятся в plain text в конфиге (не в коде, не в репозитории)
- JWT secret — отдельный от пароля
- Нет rate limiting (⚠️ см. Problems_and_bugs.md)
